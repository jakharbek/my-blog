The forward pass formula: how a network turns an input into an answer

The forward pass is what a network does every time it answers: the input goes through layer after layer, and every layer repeats the same two actions — a linear map and an activation. We take the formula apart down to the last index, compute it by hand on a small network, watch how layers bend space, and write the code.

What the forward pass is

In the article about a single neuron we took apart the formula $a = f(\mathbf{w}^{\top}\mathbf{x} + b)$. A real network is many such neurons stacked into layers: the outputs of one layer become the inputs of the next. The forward pass is the computation of the network’s answer: the input travels from left to right, layer by layer, all the way to the last layer.

The whole procedure is written in three lines:

$$\mathbf{a}^{(0)} = \mathbf{x}$$
$$\mathbf{z}^{(l)} = W^{(l)}\mathbf{a}^{(l-1)} + \mathbf{b}^{(l)}, \qquad \mathbf{a}^{(l)} = f^{(l)}\big(\mathbf{z}^{(l)}\big), \qquad l = 1, 2, \dots, L$$
$$\hat{\mathbf{y}} = \mathbf{a}^{(L)}$$

Let us read it as an instruction: put the input into the “zeroth layer”; in every layer, multiply whatever has arrived by the weight matrix, add the biases and pass the result through the activation function; whatever comes out of the last layer is the answer. If we unroll the loop, we get one long nested formula:

$$\hat{\mathbf{y}} = f^{(L)}\Big(W^{(L)}\,f^{(L-1)}\big(\cdots f^{(1)}\big(W^{(1)}\mathbf{x} + \mathbf{b}^{(1)}\big)\cdots\big) + \mathbf{b}^{(L)}\Big)$$
An analogy

An assembly line in a factory. The raw material (the input $\mathbf{x}$) passes through machines (the layers). Every machine does the same thing: it mixes the incoming parts in the right proportions (the matrix $W$), adds its own additive (the bias $\mathbf{b}$) and processes the result (the activation $f$). No machine knows about the final product: it sees only what came from the previous one. The product leaving the last machine is the network’s answer.

The main point

The forward pass does not train the network and does not change its weights: it only computes the answer with the current weights. Training comes afterwards: the answer is compared with the correct one (the loss function), and the backward pass computes how to adjust the weights.

The formula bone by bone: every symbol

All the notation of the forward pass, with sizes. We denote the number of neurons in layer $l$ by $n_l$; $n_0$ is the number of inputs.

$l$
layer number: $l = 1, \dots, L$; the superscript in parentheses $^{(l)}$ means “belongs to layer $l$”, not a power;
$L$
number of layers with weights (the depth of the network); the input “layer” $0$ has no weights;
$\mathbf{a}^{(l-1)}$
input of layer $l$: the output of the previous layer, a vector of length $n_{l-1}$; $\mathbf{a}^{(0)} = \mathbf{x}$;
$W^{(l)}$
weight matrix of the layer: $n_l$ rows and $n_{l-1}$ columns; row $j$ holds the weights of neuron $j$;
$W^{(l)}_{jk}$
a single weight: from neuron $k$ of layer $l-1$ to neuron $j$ of layer $l$ (first “where to”, then “where from”);
$\mathbf{b}^{(l)}$
bias vector of length $n_l$: one bias per neuron;
$\mathbf{z}^{(l)}$
pre-activations of the layer, a vector of length $n_l$: the weighted sums of all its neurons;
$f^{(l)}$
activation function of the layer; applied to each coordinate separately;
$\mathbf{a}^{(l)}$
output of the layer (activations), a vector of length $n_l$;
$\hat{\mathbf{y}}$
the network’s answer: the output of the last layer $\mathbf{a}^{(L)}$.

One layer is many neurons at once

Let us write the first line of the formula out coordinate by coordinate. Neuron $j$ of layer $l$ computes exactly the same formula as a single neuron: the weighted sum of its inputs plus its own bias.

$$z^{(l)}_j = \sum_{k=1}^{n_{l-1}} W^{(l)}_{jk}\,a^{(l-1)}_k + b^{(l)}_j, \qquad a^{(l)}_j = f^{(l)}\big(z^{(l)}_j\big), \qquad j = 1, \dots, n_l$$

The matrix notation $W^{(l)}\mathbf{a}^{(l-1)}$ is simply a way to compute all $n_l$ of these sums in one operation: the $j$-th row of the matrix multiplied by the input vector gives $z_j$. So the forward pass formula is the formula of a single neuron, applied to all the neurons of a layer and repeated for all the layers.

The counting rule

A layer $n_{l-1}\to n_l$ has exactly $n_l\,(n_{l-1} + 1)$ parameters: $n_l n_{l-1}$ weights and $n_l$ biases. The whole network has the sum over its layers.

The forward pass in numbers, step by step

The input is $\mathbf{x} = (1,\ 2)$. The weights and biases:

$$W^{(1)} = \begin{pmatrix} 1 & -1\\ 0.5 & 1\\ -1 & 2 \end{pmatrix},\ \mathbf{b}^{(1)} = \begin{pmatrix} 0.5\\ -1\\ 0 \end{pmatrix};\quad W^{(2)} = \begin{pmatrix} 1 & 0.5 & -0.5\\ -1 & 1 & 0.5 \end{pmatrix},\ \mathbf{b}^{(2)} = \begin{pmatrix} 0\\ 0.5 \end{pmatrix};\quad W^{(3)} = \begin{pmatrix} 2 & -0.5 \end{pmatrix},\ b^{(3)} = 1$$

Layer 1: from two numbers to three

$$\mathbf{z}^{(1)} = \begin{pmatrix} 1\cdot1 + (-1)\cdot2 + 0.5\\ 0.5\cdot1 + 1\cdot2 - 1\\ (-1)\cdot1 + 2\cdot2 + 0 \end{pmatrix} = \begin{pmatrix} -0.5\\ 1.5\\ 3 \end{pmatrix}, \qquad \mathbf{a}^{(1)} = \mathrm{ReLU}\big(\mathbf{z}^{(1)}\big) = \begin{pmatrix} 0\\ 1.5\\ 3 \end{pmatrix}$$

The first neuron received a negative sum, and ReLU “switched it off”: from here on, only a zero travels down the network from it.

Layer 2: from three numbers to two

$$\mathbf{z}^{(2)} = \begin{pmatrix} 1\cdot0 + 0.5\cdot1.5 - 0.5\cdot3 + 0\\ -1\cdot0 + 1\cdot1.5 + 0.5\cdot3 + 0.5 \end{pmatrix} = \begin{pmatrix} -0.75\\ 3.5 \end{pmatrix}, \qquad \mathbf{a}^{(2)} = \begin{pmatrix} 0\\ 3.5 \end{pmatrix}$$

Layer 3: from two numbers to the answer

$$z^{(3)} = 2\cdot0 - 0.5\cdot3.5 + 1 = -0.75, \qquad \hat y = \sigma(-0.75) = \frac{1}{1 + e^{0.75}} \approx 0.3208$$

Shapes: a check that catches half of all bugs

Every operation of the forward pass changes the size of the vector by a simple rule: an $n_l \times n_{l-1}$ matrix multiplied by a vector of length $n_{l-1}$ gives a vector of length $n_l$. The chain of sizes in our network:

$$\underbrace{\mathbf{x}}_{2} \xrightarrow{\ W^{(1)}:\,3\times2\ } \underbrace{\mathbf{a}^{(1)}}_{3} \xrightarrow{\ W^{(2)}:\,2\times3\ } \underbrace{\mathbf{a}^{(2)}}_{2} \xrightarrow{\ W^{(3)}:\,1\times2\ } \underbrace{\hat y}_{1}$$

The number of columns of $W^{(l)}$ must match the length of the layer’s input; the number of rows determines the length of its output. If they do not match, the code fails with a shape error, and that is a good thing: it is worse when the shapes happen to match but the meaning is mixed up (for example, $W$ instead of $W^{\top}$ for a square matrix).

The cost of the forward pass

For one object, a layer spends $n_l\cdot n_{l-1}$ multiply-adds, one per weight. So the whole forward pass costs roughly as many operations as the network has weights: $\sum_l n_l\,n_{l-1}$. For our network this is $6 + 6 + 2 = 14$ multiplications.

Geometry: what a layer does to space

Let us look at a layer as a transformation of space. The linear part $W\mathbf{a} + \mathbf{b}$ rotates, stretches, shears and shifts space: straight lines stay straight, parallel lines stay parallel, and the cells of a grid become identical parallelograms. The activation then bends it: ReLU folds everything that landed in the negative region onto the axes, while the sigmoid and tanh squeeze distant points towards the edges.

This is the main point of depth: each layer reshapes space a little, and by the last layer the points of different classes end up on different sides of a simple boundary. The last layer is an ordinary linear classifier or regression, but one that works in a space the previous layers have prepared for it.

Why layers collapse without activations

If we remove $f$, two layers give $W^{(2)}(W^{(1)}\mathbf{x} + \mathbf{b}^{(1)}) + \mathbf{b}^{(2)} = (W^{(2)}W^{(1)})\mathbf{x} + (W^{(2)}\mathbf{b}^{(1)} + \mathbf{b}^{(2)})$, which is again a single linear layer. Any depth without non-linearity equals one layer: parallelograms rotated several times remain parallelograms. For details, see the article about a single neuron.

A batch of objects: the same formula for many inputs

In practice a network processes a whole batch of $N$ objects at once. They are stacked as rows into a matrix $X$ of size $N \times n_0$, and the forward pass is rewritten for matrices:

$$A^{(0)} = X, \qquad Z^{(l)} = A^{(l-1)}\,W^{(l)\top} + \mathbf{1}\,\mathbf{b}^{(l)\top}, \qquad A^{(l)} = f^{(l)}\big(Z^{(l)}\big)$$

Row $k$ of the matrix $A^{(l)}$ is $\mathbf{a}^{(l)}$ for object $k$; the transpose appears because the objects are now stored as rows rather than columns. The term $\mathbf{1}\mathbf{b}^{\top}$ adds the biases to every row (in NumPy and PyTorch this is done by broadcasting). A batch of three objects through our network:

Object$\mathbf{x}$$\mathbf{z}^{(1)}$$\mathbf{z}^{(2)}$$z^{(3)}$$\hat y$
1(1, 2)(−0.5, 1.5, 3)(−0.75, 3.5)−0.750.3208
2(0, 0)(0.5, −1, 0)(0.5, 0)20.8808
3(2, −1)(3.5, −1, −4)(3.5, −3)80.9997

The second object is the zero input: the network’s entire answer to it is determined by the biases alone. Note that the answer $0.8808$ is $\sigma(2)$, the very same number as in the article about a single neuron.

Why batches

A single matrix multiplication of $N \times n$ by $n \times m$ is far more efficient for a CPU, and especially for a GPU, than $N$ vector–matrix multiplications: the data are read from memory once and processed in parallel. That is why both training and inference run in batches.

The forward pass in training: the loss and the cache

During training, the forward pass ends not at $\hat y$ but at the loss value $L$, which compares the answer with the correct $y$. For our object with the label $y = 1$ and binary cross-entropy:

$$L = -\big[y\ln\hat y + (1 - y)\ln(1 - \hat y)\big] = -\ln 0.3208 \approx 1.1369$$

An answer of $0.32$ when the correct one is $1$ is bad, and the loss is large. To reduce it, we need to know how each weight affects $L$. This is the job of the backward pass: it goes through the network from right to left and multiplies the derivatives of the layers by the chain rule. For this it needs exactly the $\mathbf{z}^{(l)}$ and $\mathbf{a}^{(l)}$ that the forward pass computed, which is why they are cached.

ModeWhat the forward pass computesWhat it stores
trainingthe answer $\hat y$ and the loss $L$all $\mathbf{z}^{(l)}$, $\mathbf{a}^{(l)}$ for the backward pass
inferenceonly the answer $\hat y$nothing extra: intermediate values are discarded immediately

This is exactly why training needs much more memory than inference: at every step, the activations of all layers for the whole batch are held in memory. In PyTorch, inference mode is turned on with torch.no_grad() or torch.inference_mode().

Code: the forward pass by hand and in PyTorch

The forward pass is a loop over the layers. Here it is in full, with a cache for the backward pass and with a batch version.

pythonimport numpy as np

relu = lambda z: np.maximum(0, z)
sigmoid = lambda z: 1 / (1 + np.exp(-z))

# The 2–3–2–1 network: a list of layers (W, b, f)
layers = [
    (np.array([[1, -1], [0.5, 1], [-1, 2]]),       np.array([0.5, -1, 0]), relu),
    (np.array([[1, 0.5, -0.5], [-1, 1, 0.5]]),     np.array([0.0, 0.5]),   relu),
    (np.array([[2, -0.5]]),                        np.array([1.0]),        sigmoid),
]

def forward(x, layers):
    a = x                                  # a⁽⁰⁾ = x
    cache = []                             # z and a of every layer are needed by the backward pass
    for W, b, f in layers:
        z = W @ a + b                      # z⁽ˡ⁾ = W⁽ˡ⁾ a⁽ˡ⁻¹⁾ + b⁽ˡ⁾
        a = f(z)                           # a⁽ˡ⁾ = f⁽ˡ⁾(z⁽ˡ⁾)
        cache.append((z, a))
    return a, cache

y_hat, cache = forward(np.array([1.0, 2.0]), layers)
for l, (z, a) in enumerate(cache, 1):
    print(f"layer {l}: z = {z}, a = {np.round(a, 4)}")
# layer 1: z = [-0.5  1.5  3. ], a = [0.  1.5 3. ]
# layer 2: z = [-0.75  3.5 ], a = [0.  3.5]
# layer 3: z = [-0.75], a = [0.3208]

# A batch: the rows of X are objects; the same formula, only X @ W.T
X = np.array([[1, 2], [0, 0], [2, -1]], dtype=float)
A = X
for W, b, f in layers:
    A = f(A @ W.T + b)                     # Z = X Wᵀ + 1bᵀ
print(np.round(A.ravel(), 4))              # [0.3208 0.8808 0.9997]

The same thing in PyTorch: nn.Linear stores $W$ and $\mathbf{b}$ and computes $\mathbf{x}W^{\top} + \mathbf{b}$, and nn.Sequential is exactly the loop over the layers.

pythonimport torch
import torch.nn as nn

net = nn.Sequential(
    nn.Linear(2, 3), nn.ReLU(),            # layer 1: W⁽¹⁾ — (3, 2), b⁽¹⁾ — (3,)
    nn.Linear(3, 2), nn.ReLU(),            # layer 2: W⁽²⁾ — (2, 3)
    nn.Linear(2, 1), nn.Sigmoid(),         # layer 3: W⁽³⁾ — (1, 2)
)
with torch.no_grad():                      # the same weights as in the article
    net[0].weight[:] = torch.tensor([[1., -1.], [0.5, 1.], [-1., 2.]]); net[0].bias[:] = torch.tensor([0.5, -1., 0.])
    net[2].weight[:] = torch.tensor([[1., 0.5, -0.5], [-1., 1., 0.5]]); net[2].bias[:] = torch.tensor([0., 0.5])
    net[4].weight[:] = torch.tensor([[2., -0.5]]);                       net[4].bias[:] = torch.tensor([1.])

X = torch.tensor([[1., 2.], [0., 0.], [2., -1.]])
print(net(X).squeeze())                    # ≈ [0.3208, 0.8808, 0.9997]
print(sum(p.numel() for p in net.parameters()))   # 20

Example 4calculation

An output with several classes: softmax

The goal

See how the last layer turns $n_L$ numbers into a probability distribution.

For $K$ classes the last layer outputs $K$ numbers $\mathbf{z}^{(L)}$, and the activation is softmax: $\hat y_k = e^{z_k} / \sum_j e^{z_j}$. For $\mathbf{z}^{(L)} = (2,\ 1,\ 0.1)$:

$$e^{\mathbf{z}} \approx (7.3891,\ 2.7183,\ 1.1052), \quad \sum \approx 11.2125, \quad \hat{\mathbf{y}} \approx (0.6590,\ 0.2424,\ 0.0986)$$
What the example shows

Softmax is not an element-wise activation: each output depends on all the $z$. The probabilities always sum to 1.

Example 5calculation

The zero input and the role of the biases

The goal

Understand that the biases set the network’s “default” answer.

Feed $\mathbf{x} = (0,\ 0)$ into our network. Then $\mathbf{z}^{(1)} = \mathbf{b}^{(1)} = (0.5,\ -1,\ 0)$, $\mathbf{a}^{(1)} = (0.5,\ 0,\ 0)$, $\mathbf{z}^{(2)} = (0.5,\ 0)$, $\mathbf{a}^{(2)} = (0.5,\ 0)$, $z^{(3)} = 2\cdot0.5 + 1 = 2$, $\hat y = \sigma(2) \approx 0.8808$.

What the example shows

Without biases, the zero input would always give $\mathbf{z} = \mathbf{0}$ in every layer and $\hat y = \sigma(0) = 0.5$, no matter what the network has learned.

Example 6calculation

“Switched-off” neurons: what ReLU does to the flow

The goal

See that a neuron with $a = 0$ completely disconnects its branch: its outgoing weights do not affect the answer.

In our example, the first neuron of layer 2 output $a^{(2)}_1 = 0$ ($z = -0.75$). Its weight in the output layer is $W^{(3)}_{11} = 2$. Replace it with $100$ or with $-100$: $z^{(3)} = 100\cdot0 - 0.5\cdot3.5 + 1 = -0.75$, and the answer does not change.

What the example shows

For a given input, only part of the network is at work. For a different input, other neurons switch on: this is how a ReLU network assembles its answer from pieces, each of which is linear.

Example 8calculationcode

Numerical stability: where the forward pass breaks

The goal

Learn two classic ways to get NaN in the forward pass and how to avoid them.

Softmax with $\mathbf{z} = (1000,\ 1001,\ 1002)$: $e^{1000}$ does not fit into a floating-point number, and we get $\infty/\infty = $ NaN. But softmax does not change if the same number is subtracted from all the $z$. Let us subtract the maximum:

$$\mathbf{z} - 1002 = (-2,\ -1,\ 0), \quad e^{\mathbf{z} - \max} \approx (0.1353,\ 0.3679,\ 1), \quad \hat{\mathbf{y}} \approx (0.0900,\ 0.2447,\ 0.6652)$$

The same goes for the sigmoid: at $z = -1000$ the naive $1/(1 + e^{1000})$ overflows. The stable version computes $e^{z}/(1 + e^{z})$ for negative $z$. And at the output of a classifier, the loss is given the logits $\mathbf{z}^{(L)}$, not the probabilities: BCEWithLogitsLoss, CrossEntropyLoss.

What the example shows

Mathematically, the forward pass formula holds for any numbers; on a machine it does not. Stable versions compute the same thing, but in a safe order.

Common mistakes

  • Mixing up the order of the indices. $W^{(l)}_{jk}$ means “into neuron $j$ from neuron $k$”. The matrix has the shape $n_l \times n_{l-1}$; in PyTorch it is (out_features, in_features).
  • $\mathbf{x}W$ instead of $W\mathbf{x}$. For a single column vector it is $W\mathbf{x}$; for a batch stored as rows it is $XW^{\top}$. Mixing them up gives a shape error or, worse, a wrong answer with square matrices.
  • Forgetting the activation between layers. The network silently collapses into a single linear layer.
  • Putting ReLU on the output of a regression where the answer can be negative: the network will be physically unable to produce it. The output of a regression uses the identity function.
  • Applying softmax and then CrossEntropyLoss in PyTorch, which already performs log-softmax internally: the probabilities are computed twice.
  • Not scaling the input. Huge $\mathbf{x}$ give huge $\mathbf{z}$, saturate sigmoids and tanh, and break training.
  • Believing that the forward pass trains the network. It only computes; the weights are changed by the optimizer step after the backward pass.

Summary

  • The forward pass: $\mathbf{a}^{(0)} = \mathbf{x}$; for $l = 1..L$: $\mathbf{z}^{(l)} = W^{(l)}\mathbf{a}^{(l-1)} + \mathbf{b}^{(l)}$, $\mathbf{a}^{(l)} = f^{(l)}(\mathbf{z}^{(l)})$; the answer is $\hat{\mathbf{y}} = \mathbf{a}^{(L)}$.
  • Each row of $W^{(l)}$ is one neuron; a layer is $n_l$ single-neuron formulas at once.
  • $W^{(l)}$ has the shape $n_l \times n_{l-1}$; a layer has $n_l(n_{l-1} + 1)$ parameters; the forward pass costs $\sum_l n_l n_{l-1}$ multiplications per object.
  • For a batch: $Z^{(l)} = A^{(l-1)}W^{(l)\top} + \mathbf{1}\mathbf{b}^{(l)\top}$.
  • Geometrically, the linear part rotates and stretches space and the activation bends it; without activations, the layers collapse into one.
  • In training, the forward pass ends with the loss and stores all $\mathbf{z}$ and $\mathbf{a}$ for the backward pass.

Test yourself

1. What is the shape of $W^{(l)}$ for a layer with 5 inputs and 3 neurons?
There are as many rows as neurons ($n_l = 3$) and as many columns as inputs ($n_{l-1} = 5$).
2. How many parameters does a 4 → 6 layer have?
$6\cdot(4 + 1) = 30$: 24 weights and 6 biases.
3. A layer: $W = \begin{pmatrix}1 & 2\end{pmatrix}$, $b = -1$, ReLU, input $(1,\ -1)$. What is the output?
$z = 1 - 2 - 1 = -2$, $\mathrm{ReLU}(-2) = 0$.
4. What happens if all the activations are removed from a 2–3–2–1 network?
A composition of linear maps is linear: $W^{(3)}W^{(2)}W^{(1)}\mathbf{x} + \dots$
5. How is a layer written for a batch $X$ (objects as rows)?
Each row of $X$ is a vector $\mathbf{x}^{\top}$, and $(W\mathbf{x})^{\top} = \mathbf{x}^{\top}W^{\top}$.
6. Why are $\mathbf{z}^{(l)}$ and $\mathbf{a}^{(l)}$ stored during training?
The derivatives of the layers are expressed through these values, for example $f'(\mathbf{z}^{(l)})$ and $\mathbf{a}^{(l-1)}$.
